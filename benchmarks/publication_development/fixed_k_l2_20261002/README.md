# Fixed-K Known-Result Development Pilot

Prospective development comparison, not either paper's official efficacy study.
One published problem family, one scheduled draw per arm, pinned local Qwen.
The family is excluded from the future main test split once these draws start.
There is no population success-rate or frontier-discovery claim.

The task uses the finite constrained least-squares segmentation problem discussed
by Truong, Oudre and Vayatis, *Signal Processing* 167:107299 (2020),
[arXiv v3](https://arxiv.org/abs/1801.00718v3). The public task defines its scope;
it does not reproduce the full review or its original experimental tables.
Published definitions are permitted background, not hidden rediscovery answers.
No author implementation, operator derivation, oracle or reference output is
supplied to the research agents. Source discovery is disabled in every arm.

The independent numerical reference enumerates admissible partitions with exact
rational squared deviations. It is not the author's dynamic program. It also
enumerates the complete finite noise law for the specified small experiment.
The verified later author-library pin supplies a separately run cross-check;
this is neither historical environment recovery nor an author-code repair.
The inspected pin supports size-one segments; all 648 finite cases, including
infeasible requests, are cross-checked without changing the author package.
All numerical cases and tolerances are frozen before research inference.

Theory remains a required deliverable. **No qualified external mathematical
referee is claimed for this pilot.** The common evaluator therefore leaves a
present derivation unconfigured, or missing when absent; full-task acceptance
cannot be earned from numerical checks alone. Product reviewer agreement is
recorded separately. A later expert or model calibration is not retroactive gold.
Numerical experiment compatibility likewise does not certify truthful source
generation or a universal statistical theorem; that needs independent source
and mathematical assessment.

The four existing draw modes use the same weights, decoding, public question,
scientific runtime, reference scale and optional global request envelope. This
is not a claim of equal tokens, computation, tool exposure or realized attempts.
Production routing/retrieval and isolated review differ from shared self-review;
authoring acceptance visibility and local workspace limits also differ. These
are recorded, not silently called a pure collaboration-content intervention.
The reverse-role arm has the exact scope and stopping caveat in the existing
publication protocol. Shared confirmation and product cohorts follow their
declared immutable seed rules; no failed draw can be restarted or salvaged.

`prepare.py` assembles this one experiment using the existing draw CLI and common
final evaluator. It is benchmark preparation, not a scheduler or repair system.
Generated deployments/configurations/task authority are frozen in a fresh local
directory before any research call. `evaluate.py` loads only each terminated
draw's declared final selection, once; it does not search earlier candidates.
No hidden result goes back to an author and no consumed run is rescored.

Cold-start each declared arm with the exact local server command and verify its
active template before the first call. Capture all terminal failures, calls,
reported tokens/cache/timings, wall time and operator preparation separately.
The task permits exact finite integration or prospectively fixed Monte Carlo;
neither the benchmark nor product harness imposes an arbitrary repetition ritual.
