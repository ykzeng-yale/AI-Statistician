## StepMix Candidate

The prospective [plan](stepmix_plan.json) records the complete Python scope in
the journal replication archive for
[StepMix](https://www.jstatsoft.org/article/view/v113i08), exact asset identities,
adapted environment and failure policy. It keeps the full three simulation grids,
the GSS application and StepMix package-comparison fits, not a five-repetition
example. Other software and the R wrapper are outside this scope.

The archived scripts hide convergence warnings and remove extreme fits before
aggregation. They do not persist per-repetition results or retained denominators.
Consequently, successful unchanged execution alone cannot qualify failure rates,
Monte Carlo precision, theoretical claims or a common full-task assessment.
These limitations are qualification findings, not permission to patch author
code, invent missing observations or use numerical agreement as a proof.

This adds a candidate latent-class/profile domain to the multi-family roster;
it does not replace the substantive TSCI B1/Card case or certify a final split.
The inspected public task records did not reveal this exact family, but absence
from that search is not absence from model pretraining or all project history.
The scripts' package-license correspondence must be verified; original data
rights remain separate. Downloaded source/data are local-only pending those terms.

Before any scientific execution, record installed versions, interpreter and input
hashes in a readiness artifact. Preserve terminal outcomes and raw diagnostics.
No model is called by this qualification. All official paper experiments remain
unactivated; Q02/Q04 on the [delivery checklist](../../docs/publication_programme.md#delivery-checklist)
remain open.
