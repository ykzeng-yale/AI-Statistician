# What The Native V3 Run Established

This is a module observation, not a successful statistical investigation. The
three terminal conditions and their costs are in [the record](observed_results.json).
No candidate evaluation ran. The numerical scorer was not used to certify theory,
and no generated code was repaired or rerun after termination.

## Observed Boundaries

1. **Runtime dependency:** stock macOS Bash lacks `mapfile`. Local GNU Bash 5.3
   resolved launch without modifying upstream. This is not a scientific failure.
2. **Prompt delivery:** stock v3 sends OpenCode a filename instruction. Both idea
   attempts asked for the file contents without invoking a tool. A separate
   one-line transport contrast used Headless's existing prompt-file support.
   Actual read/write/skill/bash/edit calls then occurred. This does not prove a
   causal success effect, and the unchanged canonical submodule remains the baseline.
3. **Research and execution:** the transport-adapted author wrote memory claiming
   completed simulation before `program_1` existed, copied the seed with `cp`
   despite the clone skill, corrected an invented filename after a read error,
   and edited `program.py`. It never invoked the supplied official evaluator.
   Its final verification claims conflict with its own missing-artifact reads.
4. **Upstream rejection:** the wrapper rejected absent rubric evidence. The outer
   process nevertheless exited zero after its configured cycle. Campaign process
   completion must therefore not be reported as scientific acceptance.
5. **Our benchmark limitation:** the task requested a complete argument and study,
   but our public scorer covered only six deterministic implementation comparisons.
   The generated bias/coverage rubrics could not be adjudicated by those metrics.
   A full study is not six unit cases, and neither is a proof. This mismatch must
   be resolved prospectively, not by changing this consumed observation's grader.

The 4B quantized model's observed behavior is not an upper bound on v3, Qwen or our
system. The run did not exhaust the allowed official evaluations; no truncation
was observed. More remote compute alone would not establish that the missing
execution had occurred. OpenCode title generations also consumed local inference
but were absent from Headless's build-only aggregate; the record includes them.

## Scientific Design Decision

Retain v3's coherent unit of work: prepare a complete candidate, execute through
the evaluator, inspect actual evidence and revise the same owned research files
through the supported next attempt. Our existing statistical preset already
selects upstream's harness-owned evaluation, so automatic handoff does not need
a new scheduler or a model-authored repair queue.

For a statistical-method task, the candidate comprises reviewable mathematical
arguments, the complete method implementation and a full simulation protocol and
executable study. Each component has a clear objective and assessment. Theory
requires justified steps and applicable assumptions; simulation evaluates declared
finite-sample performance with fair baselines and Monte Carlo uncertainty. It
cannot certify the theoretical argument. Lean remains intent-selected.

Do not make a small diagnostic simulation a mandatory extra module. Such execution
may be explicitly permitted for a task, but default authoring now hands the full
candidate to the official executor. This follows the useful evaluator-owned
principle without pretending that every scientific problem needs the same order,
one attempt, or one numerical score. A complete artifact can require substantive
revision; arbitrary fixed rounds are not a definition of rigor.

There is an important qualification: eliminating a mandatory diagnostic *stage*
does not make software checks scientifically useless. Morris, White and Crowther
recommend incremental code checking, explicit ADEMP design and Monte Carlo
uncertainty in their [simulation-study guidance](https://doi.org/10.1002/sim.8086)
(Table 1 and Sections 4-5). Our design inference is to keep relevant checks within
the declared method/evaluator workflow, without a separate agent or a numerical
"theory validation" gate. Upstream's prohibition is an execution policy for its
search/evaluation contract, not a universal theorem about optimal research practice.

Before a scientific comparison, the evaluator must actually execute the specified
complete study and the argument must have a separate, candidly qualified assessment.
Matched baseline conditions need the same task, model, access and evaluation scope.
Use the authorized SSH pool or Bouchet for a measured compute/memory need; pin and
record the changed deployment before new calls. Do not substitute smaller science
for adequate compute, or install distributed infrastructure without such a need.

The revised statistical prompt was **not** used in these observations. Its tests
establish prompt/config conformance, not that the model now follows it or completes
research. The official H/S studies and complete statistical-profile comparison
remain outstanding.
