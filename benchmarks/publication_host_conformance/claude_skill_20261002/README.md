# Native Claude Code Skill Conformance

This is a separately authorized coding-host compatibility check, not an
Anthropic scientific experiment, a Haiku baseline or a publication efficacy
result. The frozen protocol pins the already installed CLI, a Sonnet model,
the three unchanged skill files, the receipt task and the execution envelope.
It requests no statistical derivation, independent review or Lean proof.

The operator runner invokes the native host with only Read, Write and Skill;
it does not run the AI-Statistician graph or embed a host agent in the product.
It copies the package into a fresh project, installs the documented relative
link, disables user/project setting sources, and retains exact native stdout,
stderr and terminal records. Credentials enter only the host environment via
the existing loader and the operator-designated, gitignored `.env`.

For a separately authorized new host check:

```sh
.venv/bin/python benchmarks/publication_host_conformance/claude_skill_20261002/run_native_activation.py \
  --host "$(command -v claude)" --skill skills/statistical-research \
  --env-file .env --out "$FRESH_OUTPUT"
```

An existing output directory is rejected. No fallback model is configured.
The runner terminates its owned process group on timeout and preserves failure;
it neither repairs the skill nor retries the invocation. Native client-internal
requests are not independently wire-observed, so reported model usage is not a
verified account of all requests. Verify actual loaded-body and reference/tool
evidence before claiming uptake. A receipt, model agreement or host exit zero
does not establish research capability, tool breadth, usability or security.
The two official open-weight scientific studies remain unactivated.
