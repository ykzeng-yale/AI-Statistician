# Curvature IV Development Panel

Prospective development only, not either official publication experiment. This
task exercises Theory, method implementation, simulation and review in the
existing research graph. Source-only replication cannot replace that comparison.
The finite-law specialization is grounded in Section 2 of the
[TSCI paper](https://www.jstatsoft.org/article/view/v114i07), not its complete
adaptive estimator or author-code reproduction.

The entire TSCI/curvature-identification family is excluded from future main-study
test sampling once this development panel is consumed. Earlier valid-IV/GMM
development overlaps the background; this task does not establish independence
from that wider domain or constitute a new representative sampling frame.

The hidden rational-arithmetic oracle checks the task-defined estimator, not the
general TSCI theory. Independent floating-point linear-algebra checks must pass
before research calls. Submitted confirmation is checked without rerunning its
source, selecting another draft or returning hidden results to the author.
The numerical criteria include explicit finite-n allowances: they are not a
proof of unbiasedness or exact 95 percent coverage. Failed slots remain in the
coverage denominator. Mathematical full-task authority remains unqualified, so
no result can claim independently accepted full-task science.

Four modes are frozen before the first draw and consumed once in declared order.
All use the existing local Qwen weights/runtime/template and a prospectively
declared 128k context and sampling configuration. This is a new development
condition, not a rerun or escalation of the failed fixed-K panel. Resource caps
are shared, but role contexts, tool aliases, realized executions and private
confirmation schedules are not identical. Report actual differences; one family
and one draw per mode cannot estimate a general collaboration effect.

Use existing `benchmarks.publication.execute_draw` for execution and the common
final-artifact evaluator for numerical inspection. There is no new controller,
retry policy, product prompt, source patch or statistical rule in the runtime.
Operator reference preparation is not agent autonomy. All consumed artifacts
and failures remain immutable; do not salvage or resume them.
